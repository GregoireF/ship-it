# Configurability for 0.1

Decision of 2026-11-02: before 0.1, every behaviour a team may reasonably want otherwise becomes a setting. Defaults keep today's behaviour, so a repository without configuration works as before. Gates and checkpoint retention stay as they are (not chosen).

Rules for every new key:

- It goes through the existing layers (defaults, presets, user, contexts, repository, overrides, `SHIP_*`, `--set`, policy) and appears in the JSON Schemas and the [settings reference](../reference/settings.md), both generated by `tools/gen`.
- `ship config explain <key>` describes it; messages exist in English and French.
- AI agents (MCP) never change settings, and keep their safeguards whatever the configuration says: their pull requests are drafts and the secret scan runs.
- Validation errors name the key and the accepted values (codes `SHIP-E07xx`).

## Git and history

| Key | Values | Default | Behaviour |
|---|---|---|---|
| `ship.publish.update` | `rebase` \| `merge` \| `none` | `rebase` | How a branch behind its base is brought up to date before publishing: rebase with a lease (today), merge the base into it, or publish as it is. |
| `ship.commits.signoff` | `auto` \| `always` \| `never` | `auto` | Add `Signed-off-by` (DCO). `auto`: when the repository asks for it, that is when most of its last commits carry one, its CONTRIBUTING mentions the DCO, or a ruleset or app requires it. |
| `ship.commits.sign` | `auto` \| `always` \| `never` | `auto` | Sign commits. `auto` follows git's `commit.gpgsign`; `always` passes `-S` and refuses without a signing key; `never` passes `--no-gpg-sign`. |
| `ship.git.remote` | string | `origin` | Remote ship fetches from and pushes to. |
| `ship.pullRequest.base` | string | `""` | Base branch of pull requests; empty: the repository's default branch on GitHub. |
| `ship.tidy.auto` | boolean | `true` | Run `ship tidy` at the start of `ship`. |
| `ship.tidy.deleteMerged` | boolean | `true` | Delete local branches whose pull request was merged. |

## Commit and branch conventions

| Key | Values | Default | Behaviour |
|---|---|---|---|
| `ship.commits.subjectMaxLength` | integer ≥ 20 | `50` | Longest subject. |
| `ship.commits.headerMaxLength` | integer ≥ 30 | `72` | Longest header (`✨ feat(scope): subject`). |
| `ship.commits.bodyWidth` | integer ≥ 40 | `72` | Column at which bodies are wrapped. |
| `ship.commits.types` | object: type → `{emoji, branchPrefix, label, release}` or `false` | built-in table | Add a type, change its emoji, branch prefix, `kind/` label or version increment (`major`, `minor`, `patch`, `none`), or remove a built-in type with `false`. |
| `ship.commits.scopes` | list of strings | `[]` | Allowed scopes; empty: any scope. |
| `ship.commits.scopeRequired` | boolean | `false` | Refuse a title without a scope. |
| `ship.commits.scopeFrom` | `folders` \| `none` | `folders` | Where the planner takes the scope from: the changed folders, or nowhere (you write it). |
| `ship.branches.maxWords` | integer ≥ 1 | `4` | Words kept from the subject in a branch name. |
| `ship.branches.maxLength` | integer ≥ 8 | `32` | Longest description part of a branch name. |
| `ship.branches.issue` | `first` \| `none` | `first` | Put the issue number or ticket first (`feat/42-add-login`), or leave it out. |

Branch prefixes per type come from `ship.commits.types.<type>.branchPrefix`.

## Pull requests and GitHub

| Key | Values | Default | Behaviour |
|---|---|---|---|
| `ship.pullRequest.draft` | `unattended` \| `always` \| `never` | `unattended` | Replaces `draftWhenUnattended`: a draft when nobody reviewed the plan in a terminal, always, or never (AI agents: always). |
| `ship.pullRequest.labelPrefixes.kind` | string | `kind/` | Prefix of the kind labels. |
| `ship.pullRequest.labelPrefixes.size` | string | `size/` | Prefix of the size labels. |
| `ship.pullRequest.sizes` | object: name → max changed lines | Kubernetes' thresholds, as today: `XS` under 10, `S` under 30, `M` under 100, `L` under 500, `XL` under 1000, `XXL` above | Size labels and their thresholds. |
| `ship.pullRequest.sections` | object: `why`, `testing`, `issue` → boolean | all `true` | Sections of ship's own body (a repository template still wins where it applies). |
| `ship.pullRequest.reviewers` | list of logins | `[]` | Reviewers requested on a new pull request. |
| `ship.pullRequest.teamReviewers` | list of team slugs | `[]` | Teams requested on a new pull request. |
| `ship.pullRequest.assignSelf` | boolean | `false` | Assign the author to the pull request. |
| `ship.pullRequest.milestone` | `issue` \| `none` | `issue` | Put the pull request in the milestone of the issue it closes. |

## Secrets

| Key | Values | Default | Behaviour |
|---|---|---|---|
| `ship.secrets.rules` | list of `{id, pattern, keywords}` | `[]` | Extra rules: a Go regular expression, and literal keywords a line must contain for the pattern to run (as the built-in rules do). |
| `ship.secrets.disabledRules` | list of rule ids | `[]` | Built-in rules to turn off; `ship config explain` lists the ids. |
| `ship.secrets.allow` | list of fingerprints | `[]` | Findings to accept, by the fingerprint ship prints, never by value (a value in a config file would leak it). |

## Interface

| Key | Values | Default | Behaviour |
|---|---|---|---|
| `ui.language` | `auto` \| `en` \| `fr` | `auto` | Language; `auto` reads `SHIP_LANG`, then the locale. |
| `ui.reviewScreen` | boolean | `true` | Show the review screen in a terminal; `false` asks one confirmation instead. |
| `ui.accessible` | boolean | `false` | Plain, one question per line, as `--plain` and `SHIP_ACCESSIBLE=1`. |
| `ui.color` | `auto` \| `always` \| `never` | `auto` | Colours; `NO_COLOR` is always honoured. |
