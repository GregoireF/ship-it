# Sovereignty, compliance, distribution

> Nothing here is legal advice.

## Data sovereignty

| Requirement | Implementation |
|---|---|
| No code sent to an AI without consent | `ai.provider: "none"` by default. Explicit opt-in by the user or the policy. ADR-0004 |
| Central ban | `ai.allowedProviders: []` in the organisation policy |
| Minimise what leaves the machine | The secrets/PII scan runs **before** anything is sent; the diff is truncated and filtered (lockfiles, generated files and binaries excluded) |
| Traceability | The oplog records every AI call (provider, model, size sent) without the content |
| 100 % local option | `ollama` provider (or any OpenAI-compatible endpoint on the internal network) |
| Checkpoints | Strictly local: no WIP leaves the machine. ADR-0005 |
| Telemetry | **None.** Not even opt-in in v1 |

## Cyber Resilience Act

- The obligations depend on **commercial activity**, not on the license (according to secondary sources, see the research log). A personal project distributed for free would be out of scope. A commercial offer (paid support, SaaS, dual licensing) would bring it into scope.
- **Prepare anyway, at low cost, from phase 1:**
  - an SBOM generated with every release (CycloneDX or SPDX format; ❓ Go tool to choose, with no runtime dependency);
  - `SECURITY.md` with a vulnerability reporting channel;
  - reproducible builds and provenance (GitHub Actions attestations; ❓ to document);
  - a **minimal dependency budget**, which shrinks the attack surface accordingly (ADR-0012).
- ❓ Reread the official text and the Commission's FAQ before any commercial offer.

## AI Act

No obligation found on code or commits generated by AI (see the research log). ship-it adds a **disclosure in the PR** when an AI wrote the plan. It is a transparency choice, not an identified obligation.

## Accessibility (of the tool itself)

- No information conveyed **only** by color or emoji: there is always text.
- `NO_COLOR` is honored; a `--plain` mode with no spinner and no ANSI sequences (screen readers).
- VS Code extension: native VS Code components (keyboard and screen-reader accessible).
